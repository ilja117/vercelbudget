# UsBudget v6.4 — розгортання на Vercel (безкоштовно)

## Що всередині
- `public/` — застосунок: `index.html`, маніфест, service worker, іконки.
- `api/reminders.js` — щоденні нагадування (запускає Vercel Cron).
- `lib/firebase-server.mjs` — серверний доступ до бази через сервісний акаунт і перевірка входу.
- `database.rules.json` — правила бази: доступ лише для учасників зі списку `members`.
- `tests/` — тести серверної частини (`npm test`).
- `api/push-test.js` — тестове сповіщення.
- `lib/schedule.mjs` — розклад платежів, та сама логіка, що й у застосунку.
- `vercel.json`, `package.json` — налаштування.
- `tools/preview/` — локальний перегляд без CDN і живої бази (для розробки).
- `CLAUDE.md`, `PRODUCT.md`, `DESIGN.md` — правила роботи, опис продукту, дизайн-система.

Ключі йдуть окремим файлом `UsBudget-ключі-Vercel.txt`. **Не завантажуйте його в GitHub.**

## Розгортання з нуля (вже зроблено, для відновлення)
1. **GitHub.** Код уже в приватному репозиторії `vercelbudget`. Файл із ключами туди не додавайте.
2. **Vercel.** На vercel.com зареєструйтеся через GitHub (Sign Up → Continue with GitHub), план Hobby. Далі Add New… → Project → Import навпроти вашого репозиторію. Framework Preset: Other. Решту Vercel візьме з `vercel.json`. Натисніть Deploy.
3. **Ключі.** У проєкті відкрийте Settings → Environment Variables і додайте чотири змінні з файлу ключів: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_CONTACT` (ваш email), `CRON_SECRET`.
4. **Перерозгортання.** Deployments → три крапки біля останнього розгортання → Redeploy. Без цього ключі не підхопляться.
5. **Адреса.** Ваш сайт буде на `https://назва-проєкту.vercel.app` (видно на сторінці проєкту).

Назви пунктів меню у Vercel і GitHub можуть трохи відрізнятися.

## Як рахуються головні числа
- **Можна ще витратити** = внески на спільну картку за місяць − усі спільні витрати (з картки й зі своїх карток) − особисті покупки з картки.
- **На спільній картці** — стартовий залишок + внески − витрати з картки, від дати «Облік з».
- **Хто кому доплачує** — накопичувально від «Облік з» (за датою запису): хто скільки реально заплатив за спільне (зі своєї картки + частка витрат зі спільної за внесками на неї) порівнюється з частками (наприклад 60/40). Невитрачені гроші на картці боргу не створюють.
- **Особисте** — за вибраний місяць; у вкладці партнера можна увімкнути «Свій період» (з дати до дати, наприклад від зарплати до зарплати). Спільне рахується як і раніше.
- Шпаргалка для щоденних записів — у застосунку: Борги → «Як записувати, щоб не плутатись».

## Імпорт виписок банку
Записи → «Завантажити виписку» або на Android: у пошті «Поділитися» → UsBudget (встановлений застосунок).
Монобанк (CSV) і ПриватБанк (XLSX) розпізнаються самі, інші банки — якщо є стовпці «Дата» і «Сума».
Файл читається лише на пристрої. Перед додаванням — екран перевірки: галочки, категорія, «Спільне / Моє», «Розділити».
Змінені вибори запамʼятовуються як правила (`settings.importRules`); повторний імпорт не дублює записи (поле `bank`).

## Вхід і захист даних (поки вимкнено)
Код входу готовий, але вимкнений: `AUTH_REQUIRED = false` у `public/index.html`. Щоб увімкнути, пройдіть кроки нижче, потім поставте `true`, додайте на Vercel змінну `REQUIRE_AUTH=1` і задеплойте.

Без цього кроку базу може прочитати або стерти будь-хто, хто відкрив сайт. Порядок важливий: спершу акаунти, потім правила.

1. **Увімкніть вхід.** Firebase Console → проєкт → Authentication → Get started → Sign-in method → Email/Password → Enable.
2. **Створіть два акаунти.** Authentication → Users → Add user: email і пароль для кожного з вас. Скопіюйте з таблиці **User UID** кожного.
3. **Заборонiть реєстрацію чужим.** Authentication → Settings → User actions → зніміть «Enable create (sign-up)» (якщо пункту немає, це не страшно: без запису в `members` чужий акаунт все одно не побачить даних).
4. **Список учасників.** Realtime Database → Data → біля кореня «+»: ключ `members`, у ньому два записи `<UID> : true` (тип boolean).
5. **Сервісний ключ для нагадувань.** Project settings → Service accounts → Generate new private key. Увесь вміст JSON-файлу вставте у Vercel як змінну `FIREBASE_SERVICE_ACCOUNT`, потім Redeploy. Сам файл ніде не зберігайте в репозиторії.
6. **Правила бази.** Realtime Database → Rules → замініть вміст на `database.rules.json` → Publish.
7. **Перевірка.** Увійдіть у застосунок на обох телефонах. Якщо бачите «Немає доступу до бази», у повідомленні буде UID: додайте його в `members`. Нагадування: Налаштування → «Застосунок і сповіщення» → тестове сповіщення.

Відкотити можна в Rules, повернувши попередню версію (вкладка з історією).

## Нагадування
Щодня о 06:00 UTC. На безкоштовному плані Vercel запускає розклад протягом цієї години, тож нагадування приходить приблизно з 8 до 10 ранку за Києвом. У ньому платежі на сьогодні й завтра (спільні та особисті власника телефона) і непроведені за тиждень.

## Оновлення
Зміни робляться в робочій гілці й зливаються в `main` після вашого «так». Vercel розгортає `main` сам за хвилину-дві. Застосунок на телефоні оновиться під час наступного відкриття з інтернетом (за потреби закрийте й відкрийте його ще раз). При кожному релізі версія піднімається в `<title>` і в `CACHE` у `public/sw.js`.
