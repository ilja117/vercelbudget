# UsBudget — робочі правила

## Правила
- Перед злиттям у `main` або пушем поза робочою гілкою — спитати користувача «так/ні» з коротким списком змін.
- Безпеку бази без прямого прохання не змінювати. Вхід вимкнено: `AUTH_REQUIRED = false` у `public/index.html`, кроки увімкнення в README.
- Відповідати українською, коротко.
- Після громіздких змін (злиття в `main`, великий етап роботи) — спитати, чи зробити `/compact`; команду набирає користувач.

## Структура
- `public/index.html` — весь застосунок (~5300 рядків, v6.4). НЕ читати цілком: шукати `grep -n` і читати `sed -n 'A,Bp'`.
  Код шарами v3→v5: `renderAll`/`switchTab` перевизначаються обгортками; нова логіка — в останніх скриптах: `#usbudget-nav-v5` (навігація, обгортки `renderAllV5`, `switchTabV5`), `#usbudget-import` (імпорт виписок), `#usbudget-fold` (згортання блоків), `#usbudget-simple` («+» → «Що сталося?», «Звідки це число?», розкладка головної, знайомство `openIntro`).
  Теми: двигун `#usbudget-theme-engine-js` (`SKINS`, `mascotSvg`, `setThemePref`; у сховищі `usbudget_theme`: `off` / `auto` / місяць / `sk-<id>`), стилі рожевих тем — `<style id="usbudget-skins">`, форма «Глина» для всіх тем — `<style id="usbudget-clay">` (`SYM`, `coinSvg`, `applyPuffs`).
  `confirmResetToDemo` у застосунку не викликається, але потрібна `tools/preview/fakefb.js` — не видаляти.
- `public/i18n.js` — англійська поверх сторінки: словник `D` + шаблони `P`. Новий текст інтерфейсу → додати переклад.
- `public/sw.js` — офлайн-кеш. При кожному релізі піднімати версію в `CACHE` і в `<title>` index.html.
- `api/`, `lib/` — функції Vercel (нагадування, тестовий push), `tests/` — `npm test`.
- `PRODUCT.md` — для кого і навіщо; `DESIGN.md` — дизайн-система «Цінник» (кольори, шрифти, правила); `.impeccable/` — контракт напрямку.

## Підрахунки (не ламати)
- «Можна ще витратити» = внески на картку за місяць − усі спільні витрати (з картки й зі своїх) − особисті з картки (`renderGraphicHero`).
- Борг (`v4Balance`): рахується від витрат. Своє оплачене — на платника; витрати зі спільної картки й особисте з неї — на обох у пропорції внесків (старт картки — за частками). Невитрачені гроші на картці боргу не створюють. Тест: `tests/balance.test.mjs`.
- Баланс і картка (`v4Balance`, `v4Card`) — накопичувально, записи з `date` або `paidOn` ≥ `settings.modelStart` («Облік з»).
- Імпорт: поле `bank` на записі — захист від дублів; правила в `settings.importRules` (масив).

## Дизайн (коротко, деталі в DESIGN.md)
- Токени в `:root` блоку `#usbudget-graphic`: `--g-shell`, `--g-pop`, `--g-nav`, `--g-ink`, `--g-page`… Сезонні палітри `html.g-seasons[data-season]` міняють shell/pop/nav/page.
- Кольори цінників лімітів постійні (зелений/жовтий/кораловий). Текст на кольорі — чорний. Мін. 12px, без емодзі, без «картки в картці».
- Рожеві теми (v6): «Зайчик», «Кошеня», «Цукерка», «Хом'ячок», «Мочі» — `html[data-skin]`, не чіпають сезонні палітри. Нова тема = запис у `SKINS` + блок змінних `html[data-skin="id"]` + візерунок фону + переклад назви в i18n. Талісман — намальований SVG (`mascotSvg`), не емодзі; форма «Глина» (v6.4) спільна для ВСІХ тем, і місячних, і тваринних: `html.g-seasons`, змінні `--g-clay`/`--g-clay-sm`, радіуси 30–38px, без рамок, внутрішні відблиски, шрифти Rubik (заголовки, числа) + Nunito; різняться палітра й талісман (місяцям — монетка з символом місяця). Рух лише під `html.g-motion`. Текст на кольорі — темна слива/какао з `--g-ink`, не чисто чорний.
- Анімації лише під `html.g-motion` і з `prefers-reduced-motion`.

## Перевірка без CDN і живої бази
`tools/preview/build.sh` (перший раз — `cd tools/preview && npm i`), сервер на :8766, `node tools/preview/shot.cjs [tab…]`.
Теми в перегляді: `SKIN=sk-hamster node tools/preview/shot.cjs dashboard` (також `sk-bunny|sk-cat|sk-candy|sk-mochi`, `DARK=1`). Шрифти Nunito і Comfortaa підтягує `build.sh`.
Firebase у перегляді — заглушка `fakefb.js` (демо-дані завантажуються самі; знайомство вимкнено ключем `usbudget_intro`). Скріншоти дивитись вибірково: вони дорогі.
Бібліотеку xlsx у перегляді підставляти через Playwright (`page.route`, контекст із `serviceWorkers: 'block'`). Для великих чисток — порівнювати `innerText` усіх вкладок до/після.
